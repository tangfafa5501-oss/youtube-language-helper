# 标点来源与字幕轨道对照

更新时间：2026-09-02。本文件描述当前网站原生字幕路线。

## 已证实的结论

- YouTube 同一视频可能同时公布自动轨和人工地区轨；语言基础码相同不代表正文、标点或轨道类型相同。
- 请求轨道时必须保留页面提供的签名 URL，只追加白名单客户端字段和当前捕获的限时授权字段。
- 宽泛语言偏好只有在候选轨语言无歧义时才允许兼容基础码；显式地区语言必须精确匹配。
- 标点来自网站返回正文，项目不会通过翻译、语言模型或本地猜测补写句末标点。
- 句子分组只能在显示层组合已有文本，原始 cue 文本、顺序和时间保持可追溯。

## 当前实现

- `observedTimedText()` 只接受 YouTube 同源 `/api/timedtext`，验证视频 ID、语言和人工/自动轨类型。
- `applyNativeAuth()` 在安全 URL 上追加有限客户端参数以及十分钟内捕获的授权字段。
- `chooseNativeTranscript()` 按视频、轨道类型和标准化语言选择最新缓存；有地区歧义时不猜测。
- `parseJson3()` 保留所有文本事件，区分控制事件并显式报告非法结构或空正文。
- `nativeDisplayPhrases()` 忽略布局换行事件，按自然句组合显示行，并保证最终行不少于 2000ms。

## 自动断言

- 签名基础 URL 保持不变，未知客户端字段被拒绝。
- 同一视频的人工轨、自动轨和不同语言缓存不会串轨。
- 含地区代码的精确选择优先；基础语言存在多个地区候选时返回无匹配而不是猜测。
- 用户核心反例精确合并为 `And what if you were wrong about every single one?`。
- Side Panel DOM 最终为 `data-display-mode=phrases`，短行计数为 0。

## 证据边界

`artifacts/acceptance/test-browser-realdata-replay.png.json` 使用真实 JSON3 数据回放并核对运行时构建哈希，证据等级为独立测试浏览器，不等于用户当前安装环境，也不证明实时网络在所有视频和地区都能取得相同轨道。

任何轨道不可用、空正文或授权过期都必须显式失败或走同站点的受限重试，不得切换到无法核实的外部正文来源。
