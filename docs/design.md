# Video Language Helper 设计稿

2026-09-01 范围更新：用户在 Enjoy 主流程对齐后追加 B 站。B 站使用官方 `view + WBI player + subtitle JSON` 链路，优先网站现成双语轨，不新翻译。它只有 cue 级 `from/to`；句界在 cue 内时保留原 cue，不估算新时间。同一 Enjoy 式播放状态机服务两个站点。原文中“暂不开发 B 站”的早期限制被本次明确追加要求覆盖。

版本：0.1；日期：2026-08-31。

状态：M0 的 YouTube 与 B站主流程已完成真实浏览器验收，详见 `docs/m0-validation.md`。用户已批准引入 sbd 做句子分组，并将不足 2 秒的短组向后合并；这覆盖此前“只显示原条目、不做自然断句”的阶段限制。本文的翻译、AI 评分与其他后续模块仍属于历史方案，不代表已经实现或实测。

最新显示规则（2026-09-01用户范本）：默认“语段分行”，每个语段另起一行，不插空行；窄侧栏可自动折行。沿用SBD句界，再以本地启发式处理长逗号段、短插入语、括号和分号。逗号前累计至少8词才考虑切分，逗号后的短插入语≤4词先保留；括号说明独立并携带尾随标点，引号内逗号保留。没有针对范本具体单词硬编码，也没有语法模型，因此不保证所有文章的语义分段都正确。

时间规则按站点能力区分：YouTube 优先使用自动轨词级时间给自然语段独立起止点；词级轨缺失或无法可靠对齐时，按 Supadata 原 cue 时间确定性估算并明确标记，仍强制每段 2–6 秒。B站只有 cue 级 `from/to`，因此只在现有 cue 边界形成学习语段，句界落在单 cue 内时不估算新起点。原文/事件视图保留；CJK混合文字保留网站正文，旧句子时间组模式及原始模式仍可选择。

v2补充：破折号在引号和括号外作为分行边界，并重置逗号段的字数计数，避免把破折号内的短列举拆开。保留quarter-past等连字符词和10–20等数字范围；逗号后each/which/who/where/when/because/although提供额外从句线索，前段至少4词可断。其余一般逗号仍用8词阈值，非语言学保证。

最新长句补充：较长主句末尾若出现 `in/with/for/from/by/at/on/into/over/under` 引出的内容充足介词短语，可在该短语前拆分；前后至少分别 10/4 个词。该规则用于朗读停顿，不改原字幕文字，并通过 YouTube 词级对齐给拆出的两段分配独立起点。短句如 `She lives in the house.` 不拆。

当前时间分组规则：sbd@1.0.19 先确定句号/问号/感叹号及缩写等句界，保留空白，关闭换行/HTML 断句与 HTML 清理。YouTube 使用可达性规划选择边界：不足 2000 ms 才向后合并；2000–6000 ms 的一个句子保持完整，不因逗号、冒号或普通朗读停顿再拆；只有超过 6000 ms 才使用朗读停顿或词界继续拆分。长句拆分时优先选择接近 6000 ms 的最后可达停顿，并保证剩余语段不足 2 秒时能继续向后合并。完整句号边界始终优先，接受一个边界前还必须确认剩余全文也能全部落在 2–6 秒。若短句后是长静音而无法与下句合并，则可把当前结束点延至 2000 ms。自动轨词时间仍要求首尾词、60% 覆盖、顺序和 offset 合法。任何词级失败都不再清空 `phrases` 或显示 Supadata 原始 5 秒块，而是立即按 Supadata cue 时间在其自身单词间均匀估算，类型为 `youtube-estimated`。估算只服务用户明确要求的 2–6 秒播放区间，不改原字幕对象，也不声称是精确词时间。B站学习视图仍只在真实 cue 边界将多 cue 派生语段限制为 6 秒，单 cue 不伪造句内起点。

最新决定（覆盖下段早期“备用来源”和“只手动点击”决定）：用户明确要求直接移植 digest，并要求工作流参考 Enjoy Echo。已移植 youtube-digest 的 native 字幕提交和 60 次异步轮询；保存 Key 后，每个新 YouTube 视频 session 自动提交一次，StrictMode、面板重连和普通状态刷新不得重复收费调用。三点菜单的“重新获取字幕”是唯一显式再次提交入口；没有 Key 时只显示设置入口。网页直读降为实验入口；不等待 webRequest 确认，不新增网络观察权限。保留第三方原条目，不复制 digest 的文本清理和整秒取整。

2026-08-31 早期决定（自动调用部分已由上段覆盖）：用户提出参考 youtube-digest，授权必要时增加 Supadata API 填写入口。Key 仅扩展本地保存并限制 content script 访问；账户测试只查账户。新增 storage 与可选 api.supadata.ai 域权限，无 SDK、DeepSeek 或 AI 转录。

Supadata 条目来源必须单独标记。只保留服务响应顺序、文本和 offset/duration，不请求 chunkSize；尚未验证与 YouTube 原轨逐条一致，不能借此将“网站原条目一致性”标为通过。选择语言不可用时，服务可能返回其他语言，必须展示实际语言。下面的严格原轨规则继续适用于网页直读；第三方来源需另外对照验收。

## 2026-09-01 取轨修复与现成双语约束

主路径仍为 digest/Supadata native。侧栏读取公开设置语言后，默认参考网页轨道列表优先同语言人工轨：宽泛 en 允许 en-GB；显式区域只匹配该区域。无匹配时沿用设置；自动首请求使用该选择，已加载后的语言菜单允许用户明确切轨并重新请求。本次语言经后台校验，仅覆盖当前请求，不保存。网页实验轨选择仍独立。

同时保留requestedLanguage及服务language；区域请求返回基础语言不自动判错或再试。本例en-GB已实测成功275条有标点响应，但返回lang仍为en。服务按语言偏好取字幕，不承诺同语言多轨的精确ID绑定。

用户要求有网站现成双语就复用，不做新翻译。B站播放器的双语可能由字幕列表中的英语主轨和中文副轨组合，而非单条双语响应；当前实现只组合网站实际返回的英中轨，按 cue 覆盖时间聚合并保留两轨 raw，不请求翻译、不估算句内时间。已在登录态 Chrome 实测 `English(US) + 中文（简体）（网站双语）`。用户已关闭沉浸式翻译并要求停止调查。

## 1. 目标与范围

在 YouTube 原网页旁提供字幕学习侧边栏：直接读取网站已有字幕，定位与重复播放某条字幕，并按需显示 DeepSeek 译文。用户不必登录 Enjoy，配置自己的模型服务即可使用文本功能。

当前闭环：在 YouTube 或 B 站打开有官方字幕的视频 → 打开扩展 → 显示原字幕 → 点击定位播放 → 单句、循环或连续播放。当前不新增翻译请求。

| 阶段 | 包含 | 不包含 |
| --- | --- | --- |
| M0 技术验证 | 独立工程、YouTube/B站字幕轨与条目、定位播放、视频切换 | AI、翻译、语音评分 |
| M1 学习 MVP | 侧边栏、高亮、上一条/下一条、循环、末尾暂停、DeepSeek 翻译和解释、缓存与配置 | 发音评分、账号同步 |
| 后续候选 | 麦克风录音与回放、独立语音评分供应商 | 未经确认不安装其 SDK、不产生评分费用 |

暂不开发：Netflix、无字幕语音识别、本地模型、整站下载器、云账号系统、商店发布。B 站已由 2026-09-01 的追加要求纳入；SBD 本地分组不使用 AI。

## 2. 原始字幕层规则：派生分组不改动本层

1. 按原轨道顺序保留每个条目的文本和时间。原始层不合并；默认显示层按上述已批准的 SBD 规则组合，并保存成员引用。
2. 保存可获得的原始条目与时间字段；显示时只做必要的格式解析，例如实体解码。保留换行信息，不用模型改写原文。
3. 内部时间统一为毫秒，但不改变原时间含义。存在结束时间时直接使用；只有开始时间与时长时计算结束时间并记录来源。
4. 原始层不排序、不去重、不按标点或固定秒数改写。派生组可覆盖重叠原条目，但不能丢弃重复文字或缩短真实覆盖时间。
5. 时间缺失、非法或持续时间非正数时，标记异常并禁用该条目的精确循环；不能猜时间、删除条目后伪装完整。
6. 翻译可以带前后条目作为上下文，但输出必须按 cueId 一一对应，不能改变字幕条数或时间。
7. 缓存标识包含网站、视频 ID、轨道 ID/稳定指纹、原字幕内容指纹、源/目标语言、模型和提示词版本。轨道或原文变化时不能复用不匹配译文。
8. 有效轨道不存在与权限不足分开显示。字幕画在视频画面上，不代表存在可读取的字幕轨。

界面文案使用“条目/上一条/下一条”，避免把原字幕条目称为保证完整的自然句。译文区与英文区分别呈现加载和错误状态，译文等待不阻塞英文学习。

自动跟随高亮：用户向上浏览字幕时暂缓自动滚动，并提供“回到播放位置”。选中条目与当前播放条目分开记录；重叠时可高亮多个匹配条目，播放操作仍以明确选中的一条为目标。

设置页字段顺序：服务商 DeepSeek → API Key（遮罩）→ 模型名 → 目标语言 → 保存 → 测试连接。测试按钮明确提示可能产生少量费用。首期固定官方 API 地址，模型名可配置，不依赖 Enjoy 的 `default` 模型别名。

## 4. 播放行为

| 模式/操作 | 约定 |
| --- | --- |
| 点击字幕 | 用户触发定位到该条开始并播放；浏览器拒绝播放时给出提示 |
| 上一条/下一条 | 按原始条目顺序移动，不跳过短条目或重复条目 |
| 连续播放 | 只跟随进度，不自动暂停或跳转 |
| 条目末暂停 | 用户从扩展开始播放某条后，在该条结束处暂停；进入空白间隔不自动跳过 |
| 单条循环 | 在选定条目的真实起止时间之间循环；用户主动暂停后不自动恢复 |
| 拖动网页进度条 | 取消当前循环/末尾暂停任务，以用户操作为准 |
| 切换视频/字幕轨 | 取消旧控制任务和未开始的翻译任务，重置选中条目 |
| 关闭侧边栏/离开学习会话 | 释放播放控制；失联时由页面侧超时保护停止循环 |
| 多标签页 | 只控制侧边栏当前绑定的视频；切换绑定时释放旧标签页，不让旧任务抢控制 |

精确停止属于浏览器调度能力内的尽力控制；后台限频、解码和 seek 完成时间会影响精度。首轮目标是在前台正常播放条件下，抽查十条字幕的暂停/循环偏差不超过 250 ms。此数值是验收目标而非已达成承诺；若不达标记录结果并调整方案，不改字幕时间来掩盖误差。

当前快捷键在视频页与侧栏生效：`Space/K` 播放暂停、`Shift+<>` 倍速、`E/H` 跟读/听写、`A/S/D` 上一行/重播/下一行、`R/G/Esc` 录音/回放/取消、`?` 打开帮助。输入框、下拉框、音视频控件和可编辑区域不接管；字幕行聚焦时 Space 仍控制播放，工具栏或菜单按钮聚焦时 Space 保留原生激活，字母快捷键继续生效。

## 5. 技术结构

采用成熟开源框架 WXT、TypeScript 和 React，目标 Chrome Manifest V3。先在 Chrome 验收，Edge 兼容不作为首期已承诺能力。依赖版本在脚手架阶段核对并锁定；不复用旧 Electron 工程的依赖目录。

| 模块 | 职责 |
| --- | --- |
| YouTube 页面桥接 | 必要时在 MAIN world 读取播放器公开于页面的状态；仅传输最少的视频和轨道字段 |
| YouTube content script | 页面识别、字幕适配、监听视频变化、执行播放控制 |
| 后台 Service Worker | 消息路由、权限管理、DeepSeek 请求代理；不承担高频播放计时 |
| React 侧边栏 | 字幕列表、播放模式、翻译结果与错误提示 |
| 设置与存储 | 用户配置、小型状态使用 chrome.storage；字幕与译文缓存使用 IndexedDB |

消息包含协议版本、requestId、tabId（由扩展可信上下文确定）、videoId、轨道指纹和会话代号。异步返回必须再次核对会话，避免旧视频的字幕或译文覆盖新视频。

网页桥接消息视为不可信输入：验证来源窗口、类型、字段结构及长度；桥接不接受任意 URL 请求，不暴露 API Key。后台核对发送者，不把 MAIN world 的消息当成授权凭证。

字幕获取先研究 Enjoy Echo 已观察到的链路：播放器响应 → 字幕轨 → timedtext 内容。接口可能变化，应先拿真实视频验证。仅在直接获取无法满足时，再评估是否确实需要观察网络请求；不能因为原扩展申请了 webRequest 就照抄。

## 6. 权限与隐私

- 仅匹配合法 YouTube `/watch?v=` 与 B站 `/video/`、`/list/` 视频页面；只连接顶层页面，最低 Chrome 版本为 120。
- 基础权限拟为 sidePanel、storage 和必要的网站访问权限。是否需要 tabs、scripting、webRequest 逐项证明，不默认索取全站权限。
- DeepSeek 域名访问在用户启用 AI 时申请，拒绝后仍可用英文字幕和播放功能。
- 不复制 Enjoy 的商店公钥、更新地址、内部开发地址、账号同步或遥测配置。
- API Key 不写入源码、Git、日志、网页 DOM 或导出文件；不使用 chrome.storage.sync 同步密钥。
- 若用户选择保存 Key，使用扩展本地存储并限制 content script 访问，同时提示“不是系统密码保险箱”；本地有权限的软件仍可能读取。提供删除 Key 按钮。
- 只有用户显式测试连接、翻译或解释时才发送远程请求。自动翻译默认关闭，启用前提示字幕与上下文将发往 DeepSeek。
- 初版无云同步、无后台扫描浏览历史、无启动时自动上传字幕。
- 将来公开分发时，不内置开发者共享密钥；采用用户自备 Key 或另行设计受控后端。

## 7. DeepSeek 适配

使用官方 `https://api.deepseek.com/chat/completions`。供应商层暴露 translateCues 和 explainCue 两类业务操作，不让界面依赖具体 HTTP 返回格式。

- 普通翻译优先验证非思考模式以降低等待和不必要的输出；不能提前承诺延迟或翻译质量。
- 手动翻译优先级最高；自动翻译仅预取当前条目附近的小窗口，不默认翻译整段长视频。
- 返回 cueId 与译文的结构化结果，检查缺失、重复、陌生 ID；失败时不把相邻译文挪来填空。
- 原文和上下文属于资料，不作为工具指令执行；模型没有浏览器控制权限。
- 同一内容去重请求，限制并发和输出长度；用户停止后取消未开始任务并尝试中止在途请求，但已提交请求仍可能计费。
- 401 提示密钥问题，余额/配额不足停止任务，429 适度退避；不无限重试。不得自动切回 Enjoy 或其他供应商。
- 展示请求次数、供应商返回的 token 用量。货币成本只有在已核对价格和适用规则时估算，不显示伪精确费用。
- 译文缓存可单独清理、设置容量上限；缓存过期策略与结构版本必须显式定义。

## 8. 研发顺序与交付门槛

### M0：先验证最难部分

建立可加载的独立扩展，选取用户可正常观看的真实 YouTube 视频，验证人工字幕与自动字幕各至少一个。确认原始条目、时间和轨道选择正确；验证切换视频后不会残留旧数据。若只能得到 HTTP 成功但字幕为空或错视频，不能宣布通过。

### M1：建立完整学习循环

完成字幕列表、高亮、定位、循环和暂停；再接 DeepSeek、配置及缓存。DeepSeek 的真实调用需要用户在设置页提供自己的凭据；不要求用户把密钥贴进聊天。凭据缺失不阻塞非 AI 功能开发与验证。

### 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 人工字幕/自动字幕 | 保留原条目数量、顺序、文本和时间，未自然断句 |
| 重叠/重复/半句字幕 | 不擅自合并，显示和选中行为可解释 |
| 点击/上一条/下一条 | 控制正确视频、正确条目，边界按钮状态正确 |
| 视频后半段 | 使用至少 20 分钟视频，抽查前中后位置，字幕与定位均正确 |
| 单条循环/末尾暂停 | 前台抽查十条并记录偏差，目标不超过 250 ms |
| 拖动、暂停、变速 | 尊重用户操作，不反复跳回旧循环 |
| SPA 视频切换与轨道切换 | 清理旧状态，忽略迟到的网络返回 |
| 多标签页与关闭侧边栏 | 不控制错误标签页，不留下循环计时任务 |
| 无字幕/权限或网络问题 | 区分错误来源，允许重试，无自动识别或付费请求 |
| AI 未配置/失败/限流 | 原字幕仍可使用，错误清楚，不无限重试 |
| 翻译缓存和刷新 | 相同轨道复用，原文或模型变化不错误命中 |
| Key 与数据泄漏检查 | 打包文件、日志和页面消息均无密钥，未连接 Enjoy 后端 |
| 与原 Enjoy Echo 共存 | 分别启用测试；同时控制时如有冲突明确提示互斥，不声称完全兼容 |
| 构建与加载 | 类型检查、关键行为测试、生产构建、浏览器实际加载分别记录结果 |

测试针对关键行为，例如异步会话隔离、缓存失效和播放状态，不为静态文案堆叠测试。最终交付本地可加载的扩展目录、使用说明和真实验收记录；商店发布、购买 API 套餐、创建公共远程仓库不在当前范围。

## 9. 需要保留的风险

网站接口及字幕格式可能变化；网站账号和内容访问限制仍然适用。共享模型 Key 和自动请求可能产生费用。模型译文可能错译，评分服务未来加入时也不能宣称替代专业教师。单个短字幕的上下文不足是当前保留原始分段所接受的限制。

当前没有必须阻塞文档工作的未决问题。语音评分供应商、自然断句和多站点适配属于后续决策；不应为这些问题推迟 YouTube 基础版本。
