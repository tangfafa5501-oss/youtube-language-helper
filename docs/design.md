# Video Language Helper 当前设计

更新时间：2026-09-02。

## 1. 目标与范围

在 YouTube 或 Bilibili 视频旁提供字幕学习侧栏，使用网站自身可获得的字幕轨，支持双字幕、点击定位、连续播放和逐句跟读。当前不提供自动翻译、语音识别、录音评分、账号同步或商店发布。

设计底线：原始字幕是事实层，显示语句是派生层。任何分句优化都不能覆写网站原文、原始 cue 顺序或 canonical timing。

## 2. YouTube 数据流

1. 页面桥读取当前视频、播放器状态和字幕轨元数据。
2. 后台观察 `https://www.youtube.com/api/timedtext` 完成事件，验证视频、语言、轨道类型和响应大小后保存到 `chrome.storage.session`。
3. 后台向对应标签页发送 `captured`；内容脚本收到后立即解析并更新已连接侧栏。
4. 侧栏连接或页面刷新时先查询 `latest` 会话缓存；缓存拒绝、超时或格式异常时回退到所选轨正常请求。
5. 请求只保留经过白名单校验的客户端字段和限时授权字段，不接受任意来源、任意参数或超大正文。

缓存按视频、标准化语言和 `manual/asr` 类型隔离；同一键只保留最新条目，并同时限制条目数和总字符数。

## 3. 原始 cue 与显示语句

### 原始层

- JSON3 只有包含 `segs` 的事件才是文本条目；窗口和样式控制事件单独计数。
- 原始文本事件完整保留重复、空白、重叠和时间异常信息，不静默修补或丢弃。
- XML 与 JSON3 都必须先通过结构、大小和时间校验。
- 原始视图直接使用事实层，不受显示分句影响。

### 显示层

- 仅用于布局的换行事件不参与自然句组合，但仍留在原始层。
- 文本事件按开始时间和原索引稳定排序；缺失结束时间时只使用下一个更晚的开始时间作为可证明边界。
- SBD 恢复跨 ASR 事件的完整自然句；句间长静音会先切断候选运行段。
- 每一显示行必须具有合法的 `startMs/endMs`。
- 完整短句保留自身 canonical start/end；不再以低于 2000ms 为由硬合并或延长结束时间。
- 不设固定最长拆分上限，不因时长再次拆碎完整自然句。

Side Panel 的默认派生视图必须输出 `data-display-mode=phrases`。`underTwoCount` 只保留为诊断计数，不再是合格门槛。

## 4. Bilibili 数据流

- 页面环境使用现有登录态访问官方 WBI 播放器元数据和字幕地址。
- 主字幕与第二字幕独立读取；多个中文候选存在时优先网站手工简体中文轨。
- 第二轨按真实时间覆盖主轨显示行，不改变主轨原文、起止时间或定位目标。
- SPA 路由、同 BV 分 P、快速切轨和多标签页状态必须彼此隔离。

## 5. 侧栏交互

- 顶部：主字幕选择、第二字幕选择、快捷键入口和三点菜单。
- 主体：字幕状态、原始/自然语句视图、当前句高亮和双语正文。
- 底部：上一句、播放/暂停、下一句、连续播放/逐句跟读、倍速、听写和录音预留入口。
- 设置：主题、显示模式和字幕语言。未启用能力必须明确标注，不能呈现可保存但无实际用途的配置。

点击字幕发送稳定的 video/session/track/cue 身份和定位时间。导航、切轨或连接断开后，旧异步结果不得覆盖新会话。

## 6. 播放行为

- 点击字幕：先暂停，设置精确 `currentTime`，等待 `seeked`，确认实际误差不超过 80ms 后播放。
- 上一句/下一句/重播：以当前派生行顺序导航，并原子切换到 Manual。
- Auto：播放器自然连续运行，当前行随时间更新，不施加句尾暂停。
- Manual：当前句到达 `phrase.endMs` 时立刻暂停并把媒体时钟校正到句尾；不会自动续播。等待期间主动播放只定位并播放队列中的下一句。
- 倍速：支持 `0.5 / 1 / 1.5 / 2`，由内容脚本作用到当前播放器。

所有 seek 与计时边界都以 generation、会话和 Port 所有权保护；快速连击中旧 seek 会立即中止，切轨、SPA、断连或播放器元素替换会销毁旧监听器和计时器。

## 7. 技术结构

| 层 | 职责 |
| --- | --- |
| 页面桥 | 读取视频、轨道、播放器状态并执行定位/播放 |
| YouTube 内容脚本 | 消费捕获字幕、请求轨道、维护会话和播放状态 |
| Bilibili 内容脚本 | 获取官方轨道、解析双语、维护会话和播放状态 |
| 后台 Service Worker | timedtext 观察、受限缓存、设置迁移和标签页通知 |
| Side Panel | 展示、设置、快捷键和学习控制 |
| `lib/youtube-native.ts` | 原生字幕验证、缓存选择、派生语句 |
| `lib/playback-machine.ts` | 共享 Auto/Manual 状态机、精准定位、句尾暂停和监听器销毁 |
| 自动化测试 | 单元、生产 bundle 集成和测试浏览器 DOM 门禁 |

## 8. 权限与隐私

- 权限只覆盖 YouTube、Bilibili、Side Panel、必要的会话存储和请求观察。
- 不上传字幕、Cookie、浏览历史或任意标签页数据到额外字幕服务。
- 遗留配置迁移只负责删除旧存储与旧域权限，不恢复已移除功能。
- 任何新增网络域、密钥字段、账号体系或付费调用都属于新的 Level 2 设计，必须单独获批。

## 9. 交付门禁

- 修改前记录 `lib/youtube-native.ts` SHA-256；纯文档任务结束时必须一致。
- 每次代码修改都要新增或更新可重复断言，覆盖关键行为和用户核心反例。
- 涉及侧栏时必须检查最终 DOM，而不是只看算法输出或截图。
- 扩展重载验证必须记录旧 Worker 消失、新 Worker 上线、稳定等待和运行时哈希。
- 只有断言全部通过才能交付，并明确说明环境、数据来源、证据等级和仍未覆盖的边界。

当前自动门禁基线：82/82 单元测试、61/61 生产 bundle 集成测试、20/20 独立测试浏览器播放闭环。

## 10. 保留风险

- Chrome for Testing 当前未把原生 Side Panel 暴露为 Playwright page target；现有 DOM 门禁运行在真实生产 `sidepanel.html` 页面，证据等级仍是 `test-browser`。
- 用户当前 Chrome 的 `installed-real` 和实时网络 timedtext 仍需单独验收，不能由回放证据替代。
- YouTube 与 Bilibili 页面结构可能变化；桥接失败必须显式报错，不能静默回退到无法核实的数据来源。
